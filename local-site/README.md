# סטודיו אבי — גרסת HTML סטטית

המרה מלאה של `StudioAviSite.tsx` (React + Tailwind + GSAP) ל-HTML/CSS/JS ונילה,
בלי שום תלות חיצונית. נועדה לאבחון ותיקון של מנוע הווידאו ולעבודה מהירה מקומית.

```
local-site/
├── index.html              כל המבנה
├── assets/css/style.css    כל העיצוב (טוקנים זהים למקור)
├── assets/js/main.js       מנוע הווידאו + מכונת המצבים + תוכן
├── assets/img/             1.png (פוסטר), logo-brain, og, favicon, covers/
├── assets/video/           2–6.mp4  (H.264 8-bit + faststart)
├── assets/fonts/           Polin Regular/Bold
└── serve.py                שרת סטטי עם תמיכת HTTP Range (חובה לווידאו)
```

הרצה:

```bash
python3 local-site/serve.py 4455
```

השרת עולה על כל הממשקים, כך שאפשר לפתוח את האתר גם מהנייד באותה רשת —
הכתובת המדויקת מודפסת בהרצה. להגבלה למחשב בלבד: `python3 local-site/serve.py 4455 127.0.0.1`

## התנהגות הניגון

כל קטע מתנגן **פעם אחת בלבד** ונעצר קפוא על הפריים האחרון, ממתין ללחיצה.
אין `loop` בשום שלב — גם לא בקטע הסיום (6.mp4) שמשמש כרקע האתר.
קפיצה בסרגל העמודים מציגה את הפריים האחרון של הקטע הרלוונטי בלי לנגן אותו
מחדש (`VideoStage.play(name, { still: true })`).

## שורש התקלה: הקבצים ב-Supabase

בדיקת הקבצים באיחסון החיצוני (`storage/v1/object/public/videos`):

| קובץ | קודק | moov / faststart | מנגן בכרום־פיירפוקס־אדג' |
|---|---|---|---|
| 2.mp4 | `avc1` H.264 | בהתחלה ✅ | ✅ |
| 3.mp4 | **`hvc1` H.265 10-bit** | בסוף הקובץ ❌ | ❌ |
| 4.mp4 | `avc1` H.264 | בהתחלה ✅ | ✅ |
| 5.mp4 | **`hvc1` H.265 10-bit** | בסוף הקובץ ❌ | ❌ |
| 6.mp4 | **`hvc1` H.265 10-bit** | בסוף הקובץ ❌ | ❌ |

HEVC 10-bit לא נתמך בדפדפני דסקטופ. שלושה מחמשת הקטעים פשוט לא מתנגנים —
**זה המסך השחור.** בנוסף ה-`moov` שלהם בסוף הקובץ, כך שהדפדפן חייב להוריד
14–17MB לפני הפריים הראשון.

הקבצים המתוקנים כבר קיימים בפרויקט (`assets/video/`, כולם `avc1`, 3.6–4.8MB
במקום 12–17MB) — הם פשוט מעולם לא הועלו חזרה ל-Supabase.

### מעבר ל-Supabase

ב-`assets/js/main.js`, שורה ראשונה בבלוק התצורה:

```js
const USE_SUPABASE = false;   // → true אחרי העלאת הקבצים המתוקנים
```

לפני שמעבירים ל-`true` צריך להעלות ל-Supabase את חמשת הקבצים מ-`assets/video/`
(ואת `1.png`) — אחרת 3/5/6 יחזירו מסך שחור בדיוק כמו היום.

## הבאגים שתוקנו בקוד

### 1. הבזק של הסרטון הקודם ואז מסך שחור
בגרסה הקודמת `reveal()` הופעל גם מהנגן **הלא-פעיל** דרך `onCanPlayThrough`
ו-`onTimeUpdate`. הנגן הישן, שהמשיך לרוץ מוסתר, חשף את עצמו מחדש → הקטע
הקודם חזר לרגע. ואז טיימר הקרוספייד שלו ניקה בטעות את השכבה של הקטע **החדש**
→ שתי השכבות ריקות → מסך שחור.

**התיקון:** לכל בקשת ניגון יש טוקן (`VideoStage.token`). רק הנגן הנכנס של
הטוקן הנוכחי יכול להיחשף; כל מאזין בודק את הטוקן לפני שהוא פועל, וכל בקשה
חדשה מבטלת את המאזינים של הקודמת דרך `AbortController`.

### 2. שני הנגנים ניגנו במקביל
הישן המשיך לרוץ מוסתר — רוחב פס כפול ואירועי `ended` מיותרים.
**התיקון:** מיד אחרי הקרוספייד הישן נעצר ומשוחרר.

### 3. הורדה כפולה של כל קטע
ה-preload היה אלמנט `<video>` שלישי מוסתר + `<link rel="preload">` בתוך ה-body.
**התיקון:** הנגן שהתפנה בקרוספייד הוא שטוען מראש את הקטע הבא. אפס הורדות כפולות,
והמעבר הבא מיידי.

### 4. קפיצה בסרגל העמודים שברה את המעברים
`jumpTo` לא ביטל את ה-callback של המעבר שרץ, כך שסיום של קטע ישן הזיז את
האתר לעמוד לא נכון. בנוסף `endedFor` ננעל לפי `src`, כך שקטע שכבר נוגן פעם
אחת לא שיגר `ended` שוב — והאתר נתקע.
**התיקון:** `jumpTo` מקדם את הטוקן, מה שפוסל אוטומטית כל סיום ישן; והנעילה
היא לפי מזהה ניגון ולא לפי `src`, כך שאותו קטע יכול להתנגן שוב ושוב.

### 5. כשל טעינה נבלע בשקט
`onError` פשוט התקדם הלאה, וכך האתר "התקדם" אל מסך שחור בלי שום סימן.
**התיקון:** מוצגת הודעה מפורשת עם שם הקובץ וקוד השגיאה, והפריים הקודם נשאר
על המסך במקום להתרוקן.

### 6. `overflow-x` על html/body ביטל את גלילת העמוד
`overflow-x: clip` הופך, לפי מפרט CSS, גם את `overflow-y: visible` ל-`clip` —
כלומר העמוד לא נגלל בכלל. במקור זה הופיע גם על `html` וגם על `body`.
**התיקון:** `overflow-x: hidden` על `html` בלבד (hidden הופך את הציר השני
ל-`auto`, כלומר גלילה נשמרת), ובלי שום `overflow` על `body`.

### 7. מיקום לוגי במקום פיזי ב-RTL
סרגל העמודים וכפתור הוואטסאפ מוקמו עם `inset-inline-start/end`, שמתהפכים
באתר RTL — הסרגל קפץ לימין והוואטסאפ לשמאל.
**התיקון:** `left` / `right` פיזיים, בדיוק כמו במקור.

### 8. הסרגל בנייד חפף לכפתור הוואטסאפ
תשעה פסים ברוחב 30px + מרווחים = 362px ב-viewport של 375px.
**התיקון:** רוחב `min(300px, 100vw - 160px)` עם פסים גמישים.

### 9. רשת ביטחון שהציגה שגיאת שווא
טיימר ה-8 שניות הציג הודעת שגיאה גם כשמדובר פשוט בחיבור איטי.
**התיקון:** הטיימר חושף את הקטע ומדווח לקונסול בלבד; ההודעה למשתמש שמורה
לאירוע `error` אמיתי.

### 10. אנימציות החשיפה יכלו להשאיר תוכן בלתי-נראה
כל אלמנט `[data-rv]` מתחיל ב-`opacity:0` ומתגלה דרך `IntersectionObserver`.
אם ה-observer לא זמין או לא נורה — התוכן פשוט לא מופיע לעולם.
**התיקון:** נוספה `revealObserver.sweep()` שרצה גם בכל אירוע גלילה וגם בעת
האתחול, וחושפת כל אלמנט שכבר נמצא באזור הנראה; ובדפדפן בלי `IntersectionObserver`
הכול נחשף מיד.
